# Pocket — application audit, 2026-10-12

## Context

Third audit round. Rounds one (#683/#685, Sept) and two (#786/#795, last week) swept
security/infra, decimal-safety, concurrency and visual nits. This round went deeper into
the areas those did not name: shared-resource mutation paths, the cash-boundary and
transfer invariants end-to-end, tax rules, rate-limit/resilience, and a **live** browser
walkthrough of every route at phone/tablet/desktop widths on the demo seed.

This file _is_ the report. Fixes are to be carried out by other models, so every finding
has an ID, a severity, a `file:line`, a concrete failure scenario, **one** preferred fix,
and a verification step. Findings are grouped into PR-sized batches like #683/#685.

**Evidence tags:** `[read]` = I verified by reading the code at HEAD `bc905ea6`;
`[live]` = reproduced in the running dev app; `[sweep]` = reported by a static sweep and
plausible but not independently re-read — the fixer should confirm before changing
(sweep line numbers may drift by a few lines).

**Headline:** two live-reproduced defects (D1 rate-limit bucket shared by every user;
B3 income totals disagree between pages), four silent-wrong-number bugs in the core
(B1 TWR counts transfers as return, B2 FX falls back to 1:1, B4 transfers land at
zero cost, B7 allocation double-counts at-cost holdings), one shared-data write path that
bypasses the admin gate (A1), and one UX cascade (a 429 renders as "API down"/"not found").

## Method & coverage

- Three static sweeps (security/auth · correctness/perf · web UI) against the repo's own
  review checklist (`.claude/skills/pocket-review-invariants`); ~25 top candidates re-read
  by me. `npm audit`, `npm run lint`, en/id key diff run directly.
- Live pass: Playwright (Mullion's Chromium) over 21 routes × {390×844 touch, 820×1180
  touch, 1440×900} + dark mode, on `make dev` with the demo seed. Screenshots and per-route
  metrics in the session scratchpad (`shots/`, `shots2/`).
- Prior-round files were deprioritised; open issue #691 (Insights numbers) is referenced,
  not re-found.

**Two things that looked like bugs but are not:** `/id/holdings` showing "Tidak dapat
menjangkau API" and the first instrument page showing "Instrument not found" were both the
API answering `429 Rate limit exceeded` (see D1) — there is no locale bug and no
instrument bug. The real defect is that the UI cannot tell a 429 from "down" or "empty"
(G1).

## Batch A — security & auth (`fix(security)`)

### A1 · High (multi-tenant) / Medium (today) · `[read]` — `POST /instruments` rewrites shared rows without an admin gate

- `services/api/src/routes/instruments.ts:322` (`preHandler: app.authenticate` only) →
  `services/instruments.ts:103-116` `healInstrument` applies `instrumentUpgrade`
  (`:53-77`): changes `assetClass` (equity/mutual_fund → anything non-equity), re-pins
  `market`+`currency`, back-fills ISIN/WKN on the **existing global row**.
- Scenario: any user re-posts an existing `(market, symbol)` with `assetClass:"bond"`;
  the row becomes a bond for everyone; `PUT /instruments/:id/manual-price`
  (`services/instruments.ts:357`, bond-only, any user) then sets its price and writes a
  `prices` row — every holder of that equity is revalued. Issue #362 deliberately left
  `POST` open _for creation_ and gated `PATCH`; the upgrade path is the gap it missed.
- Fix: split `instrumentUpgrade` into two tiers. **Everyone:** the deliberate
  same-family refinements that #111 relies on (`mutual_fund → etf`, ISIN-as-symbol →
  ticker, ISIN/WKN null-back-fill, bond-term back-fill). **Admin only** (or the admin
  `PATCH`): cross-family `assetClass` changes (equity/mutual_fund → bond/crypto/cash/
  gold) and `market`/`currency` re-pins. Thread an `actor: { isAdmin }` option through
  `findOrCreateInstrument` — it is called from the import-confirm/materialize paths and
  the typeahead, not only the route. Log every tier-2 upgrade with userId.
- Verify: API tests — non-admin `POST` with `assetClass:"bond"` against an equity row
  leaves it unchanged; non-admin `POST` with `etf` against a `mutual_fund` row still
  refines (keeps #111); admin `POST` re-pins market.

### A2 · Medium · `[read]` — every PAT is admin when `NODE_ENV` is unset

- `plugins/env.ts:9-13` defaults `NODE_ENV` to `"development"`;
  `plugins/auth.ts:203` sets `isAdmin: app.config.NODE_ENV === "development"` for PATs.
  Dockerfiles/prod compose set `production`, so exposure is bare-`node`/custom deploys —
  but the comment at `:175-177` promises "never outside local development", and the
  default makes that fail-open.
- Fix: change the schema default to `"production"` (fail-closed); `.env.example` and
  `docker-compose.yml` already/explicitly set `development` — confirm `.env.example`
  does. Add a test: `buildApp({})` with no `NODE_ENV` → PAT `isAdmin === false`.

### A3 · Medium · `[read]` — login throttle is one bucket for all users

- `apps/web/src/auth.ts:184-191` `authorize()` POSTs to `/auth/local/login` with no
  `x-forwarded-for`; the API's `@fastify/rate-limit` (10/min on login,
  `routes/auth.ts:77`) keys by IP → every local login counts against the web
  container's IP. Ten wrong passwords from anyone lock everyone out for a minute; no
  per-account throttle exists.
- Fix: Auth.js v5 passes `request` as the second `authorize` arg — forward its
  `x-forwarded-for` first hop (same helper as `api/backend/[...path]/route.ts:45-53`),
  and add a per-email sliding window on the API (e.g. 5/min per normalized email in
  memory, reset on success). Same for `/api/local-auth-setup/route.ts:135`.
- Verify: two IPs, one bad password ×10 from IP A → IP B still logs in.

### A4 · Medium · `[read]` — OIDC login can rebind a local account by e-mail alone

- `plugins/auth.ts:231,293-310`: JIT-insert collides on `email`, and if the existing row
  is `local|…` it is rewritten to the OIDC `sub` — no `email_verified` check.
- Scenario: Authentik lets a user set/claim an unverified e-mail matching a local user →
  account takeover on first OIDC login.
- Fix: require `payload.email_verified === true` for the migration branch; otherwise
  401 `{error:"email_unverified"}`. Document in README's self-host section.
- Verify: unit test with `email_verified:false` → 401, rows untouched.

### A5 · Low · `[read]` — admin audit log shows the _oldest_ 100 rows

- `routes/admin.ts:36-39`: `orderBy(adminAuditLog.at).limit(100)` then `.reverse()`.
- Fix: `orderBy(desc(adminAuditLog.at))`, drop the reverse. Verify: >100 rows → newest
  visible.

### A6 · Low · `[read]` — inbox documents with the same filename share one storage object

- `services/api/src/storage/inbox.ts:46` key = `inbox/{user}/{category}/{year}/{filename}`.
  Re-uploading a different PDF with the same name overwrites the first document's
  object; deleting either row deletes the shared object; the duplicate-race branch
  deletes the winner's object.
- Fix: append the document id (or 8 chars of `contentHash`) to the key before the
  extension. Verify: upload two different PDFs named `report.pdf`; both download.

### A7 · Low · `[sweep]` — side-effecting GETs are reachable with a read-scoped PAT

- PAT read scope is purely method-based (`plugins/auth.ts:195`). GETs that write or
  spend quota: `/instruments/:id/fundamentals` (updates the row), `/fx-rate` (inserts
  `fx_rates`), `/networth` + `/holdings` (`enqueueInstrumentMetadata`),
  `/portfolios/:id/history` (`fetchBenchmarkPrices` persists), `/instruments/enrich`.
- Fix: route-level `config: { scope: "write" }` honoured by `authenticate` for the
  genuinely mutating ones (`fundamentals`, `enrich`), and make the others
  write-through-cache only (no enqueue) when `request.user.authMethod === "pat"`.

### A8 · Low · `[sweep]` — log redaction gaps and raw error leakage

- `app.ts:113-133` redacts auth/cookie/phone/pin but not `token`, `password`,
  `apiKey`, nor the local-auth and storage secret env vars; Fastify's default `req.url`
  log captures `/storage/*?exp=&sig=` signed URLs; pytr stderr is copied into
  `trConnections.lastError` and returned to the user (`tr/_shared.ts:11`); the
  `diagnose-documents` route returns raw storage error text.
- Fix: extend `redact.paths`; log `req.url` without query for `/storage`; store a
  sanitized one-line `lastError` and keep the raw text at `error` log level only.

### A9 · Low · `[sweep]` — unvalidated strings interpolated into provider URLs

- `routes/transactions.ts:33-37` `/fx-rate` (`from`,`to`,`date` free strings →
  `services/fx.ts:78` URL); `routes/instruments.ts:37` `range` free string →
  `yahoo-finance/provider.ts:113`, `twelve-data.ts:174`. Not host-SSRF (bases fixed),
  but query injection into third-party calls and 500s on garbage.
- Fix: zod `enum` for `range`, `/^[A-Z]{3}$/` for currencies, ISO-date regex for `date`;
  `encodeURIComponent` at the call sites.

### A10 · Low · `[sweep]` — subprocess inherits the whole environment

- `services/pytr/process.ts:39`, `runner/core.ts:67-68` spawn with
  `{ ...process.env, ...extraEnv }` → pytr/Playwright can read `DB_ENCRYPTION_KEY`,
  `AUTH_LOCAL_SECRET`, `DATABASE_URL`.
- Fix: allow-list (`PATH`, `HOME`, `LANG`, `TMPDIR`, proxy vars) + `extraEnv`.

### A11 · Low · `[sweep]` — encryption key and downgrade handling

- `services/encryption.ts:18` slices the key to 32 bytes with no length check (short
  key fails at first encrypt); values lacking the `enc:` prefix are returned as plaintext
  (`:42-44`), so a plaintext write is silently accepted.
- Fix: validate 32 decoded bytes at startup (fail fast); make plaintext passthrough
  opt-in (`allowPlaintext` for the migration path only).

### A12 · Low · `[sweep]` — password/token lifecycle edges

- Changing a password does not revoke PATs; admin `set-password` on an OIDC user
  creates a parallel local login that outlives Authentik disablement; `AUTH_LOCAL_SECRET`
  has no min length and no `_FILE` support; local JWT has no `iss`/`aud`.
- Fix (one PR): min 32 chars for the secret + `_FILE`; set `iss`/`aud` on local JWTs and
  verify them; on password change, revoke PATs unless `keepTokens` is passed; forbid
  `set-password` for OIDC-only users unless the admin passes `allowLocalFallback`.

### A13 · Low · `[read]` — dependency advisories

- `npm audit`: 5 high, all `braces`/`micromatch`/`fast-glob` via `eslint-config-next`
  (dev-only, not in the runtime image). `next-auth` is on `5.0.0-beta.32`.
- Fix: `overrides: { braces: "^3.0.3" }` in root `package.json` (confirm with
  `npm ls braces`), re-run audit; track next-auth GA.

## Batch B — money, boundary & transfer correctness (`fix(core)`)

### B1 · High · `[read]` — TWR treats depot transfers as investment return

- `packages/core/src/twr.ts:178-195` and `services/api/src/services/snapshots.ts:130-144`
  build `effectiveFlow` from trade types and real-series dividends only; the comment at
  `snapshots.ts:114-116` explicitly excludes `transfer_*` "because they land in cash".
  A `transfer_in` moves holdings market value with zero flow → `chainIndex` books the
  whole transfer as a +X% day (or drops the day if >50%). Everything downstream of the
  TWR index — history chart "Performance" mode, max drawdown, volatility/Sharpe,
  benchmark active return (#691) — is corrupted for anyone with a Depotübertrag.
- Fix: in both sites treat `transfer_in`/`transfer_out` as a flow equal to the shares'
  market value **on that date** (`qty × priceAt(date)`, converted), falling back to
  carried cost when unpriced — this makes the transfer day exactly return-neutral, which
  is the economically correct TWR treatment. Add the same branch for legacy
  `bonus`+`kind:"transfer_in"` rows until they are migrated. **Scope note for the
  issue:** this is the TWR _securities-sleeve_ flow definition only; `boundaryFlowPoints`
  / `transferFlowPoints` (contribution + XIRR) keep valuing transfers at carried cost —
  CLAUDE.md warns explicitly against collapsing those two definitions, so do not "share"
  the helper.
- Verify: core test — flat prices, `transfer_in` on day 2 → index unchanged; snapshots
  test mirrors it.

### B2 · High · `[read]` — a missing FX rate silently converts 1:1

- `services/api/src/services/fx.ts:254-259` `makeFxRateFn` returns `"1"` for any
  unknown pair; `getFxRates` (`:143-160`) reads only _today's_ cached row with no
  carry-forward. A Frankfurter outage or a holiday morning makes every IDR amount count
  as EUR; `recordDailySnapshots` persists the result.
- Fix: `getFxRates` falls back to the latest row ≤ today (reuse the carry-forward in
  `getFxRatesForDates:240-248`) and, if still missing, the rate fn returns `null`;
  `convert()` callers surface an `fxMissing` flag (same pattern as `valuedAtCost`) and
  the snapshot job **skips** the portfolio for that day rather than writing a 1:1 value.
- Verify: test with no EUR/IDR row → holding reported `fxMissing`, no snapshot row.

### B3 · High · `[read] [live]` — income totals disagree across pages

- `routes/transactions/shared/helpers.ts:52-57` `incomeCase` values dividend/coupon as
  `price × quantity`; every importer stores lump-sum dividends with `quantity:"0"` and
  the amount in `price` (`pytr/mapper.ts:112-113`, tr-csv, tr-pdf, ibkr, dkb). The SQL
  also ignores `fees`. **Live:** Activity header "Income €284.25 all time" vs Income page
  "Lifetime received €570.40" on the same demo data.
- Fix: mirror `cashFlow()` exactly: `when type in ('dividend','coupon') then case when
quantity = 0 then price else price*quantity end - fees`. Add the `status='confirmed'`
  filter the summary currently lacks (B5). Add a SQL-vs-`cashFlow` parity test using a
  `qty=0` dividend fixture.
- Verify: primary — a parity test asserting the SQL summary equals Σ `cashFlow()` over
  the same confirmed rows (that is the invariant; the two pages may legitimately differ
  in scope/period, so "pages agree" is the secondary check, after decomposing the demo
  gap: interest inclusion, `tax` subtraction, which seed rows have `qty = 0`).

### B4 · High · `[read]` — transfers imported at price 0 (zero cost basis)

- `services/pytr/mapper.ts:144-151` sets `price = "0"` for `transfer_in`/`transfer_out`.
  Downstream: `transfer_in` lands at zero cost → a later sale shows 100% gain and full
  taxable proceeds; inside-boundary `transfer_out` is valued at the row price
  (`packages/core/src/contributions.ts:175-179` uses `transferInflow` = qty×price+fees)
  → outflow 0 while value drops (the #736 class). IBKR may do the opposite — land
  `transfer_in` at `positionAmount`, possibly market value (`ibkr/mapper/core.ts:264-270`,
  `[sweep]`, verify against the Flex spec).
- Fix: (1) pytr mapper: use the event's acquisition price when the detail sections carry
  it, else emit the draft with `confidence 0.5` + `attention: "needs_cost_basis"` and
  make `imports/confirm` reject `transfer_in` drafts with `price = 0` until the user
  fills it in the review screen (new required field). (2) `contributions.ts` inside walk:
  value `transfer_out` at running average cost (reuse the outside walk's pool logic
  `:280-295`), never the row price. (3) IBKR: confirm field semantics; if `positionAmount`
  is MV, use `costBasisMoney` only.
- Verify: core test — inside boundary, buy 10@100, `transfer_out` 10 with price 0 →
  outflow 1,000; mapper test — TR transfer without price → draft flagged.

### B5 · Medium · `[sweep]` — list summary counts drafts/archived rows

- `routes/transactions/list.ts:60-79, 215-237` build `conditions` without a `status`
  filter before `computeConvertedSummary` → unconfirmed drafts feed Invested/Proceeds/

### B6 · Medium · `[read]` — backfilled net worth uses a different definition than live

- Fix: extract `netWorthInputs(transactions, cashCounted, fx, display)` in

- Verify: after a recompute, Reports card and Savings chart end-point agree.

### B7 · Medium · `[read] [live]` — allocation double-counts holdings valued at cost

- Core `valuation.ts:170-184` returns at-cost holdings with `currency: null` but adds
  their value to `exposureByCurrency`; `allocation/compute.ts:85-106` only adds

  appears in its own asset class **and** in Cash; slices sum to more than total.

- Fix: in `compute.ts:85` use `h.currency ?? h.costCurrency` (expose `costCurrency` on
  `HoldingValuation` if not already). Test: one unpriced holding, no cash → cash slice 0.

### B8 · Medium · `[sweep]` — `totalReturnPct` double-counts mergers/reinvestments

- `routes/transactions/shared/contributions.ts:111-119`: `positiveFlows` includes every

- Fix: exclude `kind in (merger, reinvestment)` sells from `positiveFlows` (XIRR path is

### B9 · Medium · `[sweep]` — outside-boundary contribution walk ignores splits

### B10 · Medium · `[sweep]` — period P&L includes deposits; XIRR anchor mismatch

## Batch C — tax (`fix(tax)`)

### C1 · Medium · `[read]` — harvest suggestions include §23 assets (gold, crypto)

- `packages/core/src/tax/suggestions.ts:32-36` iterates every open trade with no
  asset-class filter, while `allowanceUsageYTD` skips non-eligible classes. Suggests
  realising gold/crypto gains "to use the Sparerpauschbetrag" — wrong regime.
- Fix: skip trades whose instrument is not `isTaxFreeEligible`/in `assetClasses`.

### C2 · Medium · `[read]` — fund distributions get no Teilfreistellung

- `packages/core/src/tax/compute.ts:46-53` adds `incomeGross` (from
  `tradeLog.dividendsByYear`) to the general pot unadjusted; only trade legs and
  Vorabpauschale use the TF multiplier. `trade-log/compute.ts:255,366` comments say
  "gross; tax.ts applies Teilfreistellung when netting it against the FSA" — but
  `routes/transactions/tax.ts` only passes `tfRates` for trades, so nobody applies it.
  Equity-ETF distributions should be 30% exempt (15% mutual funds).
- Fix: carry per-instrument income in `dividendsByYear` (or a parallel
  `incomeByInstrumentYear`), apply `effectiveMultiplier(tfRates[instrumentId])` in
  `compute.ts` before pooling; fix the misleading comments.

### C3 · Medium · `[read]` — loss pots don't net in the permitted direction

- `tax-helpers.ts:8-11` `computePotUsage` clamps each pot at 0 independently; a negative
  general pot never offsets stock gains (allowed under §20(6) EStG — stock losses are
  the ring-fenced ones). Fix: net a negative general subtotal against the stock
  subtotal before clamping. Confirm the rule with the user before changing.

### C4 · Medium (ID users) · `[sweep]` — Indonesian final tax applied to every disposal

- `routes/transactions/tax-helpers.ts:261-285` applies 0.1% to gold, crypto, EU ETFs
  and bonds; only IDX-listed shares are in scope. Also stores a display-converted
  amount under the native currency label (`:324`).
- Fix: filter to `market === "IDX" && assetClass === "equity"`; keep native currency.

### C5 · Low · `[sweep]` — rates and periods

- `[read]` The rate is the holder's configured `capitalGainsTaxRate`
  (`routes/transactions/tax.ts:196,445`) with a fallback of `"0.25"` when unset (core
  `tax/compute.ts:10` same default). The demo holder has 26.375% configured, which is why
  the live Tax page shows it — so this is only wrong for holders who never set a rate
  (Soli omitted by default); `churchTax` is stored and echoed but never folded into a
  rate. Fix: default `0.26375` and derive the effective rate from `churchTax` when set.
  `LONG_TERM_DAYS = 365` with `>=` (§23 is _more than_ one year; leap years). Average
  method uses `episode.entryDate` so a recent top-up inherits long-term status.
  TF rate hardcoded per asset class (`tax-helpers.ts:202-208`) — bond/real-estate ETFs
  get 30% unless overridden. No Basiszins table — Vorabpauschale silently 0 when the
  broker doesn't supply it. `userPreferences.costBasisMode` is never read server-side
  (only `?costBasis=`).
- Fix (one PR): 26.375% default with optional KiSt; `> 365`/date-arithmetic for the
  holding period; per-lot dates for average-method long-term flags; Basiszins table by
  year (fixer to source the official values); resolve `costBasisMode` from prefs in a
  shared helper when the query is absent.

## Batch D — performance & resilience (`fix(api)`)

### D1 · High · `[read] [live]` — one 100-req/min rate-limit bucket for every user

- `plugins/security.ts:12-15` registers `@fastify/rate-limit` globally (default
  `RATE_LIMIT_MAX=100`, `1 minute`, keyed by IP). All RSC loaders go through
  `apps/web/src/lib/server-api/_shared.ts:61-74` → `createApiClient` with only a token —
  **no `x-forwarded-for`** — so every server-rendered page for every user counts against
  the Next container's single IP. One page ≈ 10–15 API calls (Holdings `page.tsx` has
  11 awaits). **Live:** a single browser walking the routes tripped it; the API
  answered `{"error":"Rate limit exceeded, retry in 16 seconds"}` and every page
  rendered "Can't reach the API" / "Instrument not found". `authorize()` (A3) shares the
  same bucket. In prod behind Traefik the client-side proxy forwards XFF, but RSC
  fetches do not, so two active users can lock each other out.
- Fix: (1) key the limiter per credential — `keyGenerator: sha256(authorization
header)` when a Bearer is present, else IP. (Do **not** key on an unverified JWT
  `sub`: anyone could forge a token naming a victim's sub and exhaust their bucket.)
  (2) forward the first
  XFF hop from RSC loaders (`createApiClient({ headers })` — add the option) and from
  `authorize()`; (3) raise the default to something page-shaped (e.g. 600/min) and
  document it; (4) web: surface 429 as its own state (G1).

## Batch G — UX proposals (bold; each grounded in something observed)

### G1 · Error taxonomy instead of one "Can't reach the API" card

- Observed: 429 → "Can't reach the API" (Holdings/Activity/Insights/Settings) and
  "Instrument not found" (instrument page); `loadNetworthTax` returns `[]` on API-down
  so Tax shows the _empty_ copy; Reports silently renders a partial page (only the Tax
  reports card) when other loaders fail. Users cannot tell "retry in 16 s" from "your
  session expired" from "you have no data".
- Proposal: `PortfolioResult` grows `status: "ok"|"empty"|"unauthorized"|"rate_limited"
|"unavailable"` with `retryAfter`; one `<DataState>` component renders the right
  copy + an inline **Retry** (router.refresh) and, for `rate_limited`, a countdown.
  Never reuse "not found" for a transient error. Pair with D1.

### G2 · One gain story

- Observed on one scope: Holdings right rail "All-time +€12,841.35 (+71.39%)", sidebar
  "+71.39% all-time", Savings "Gain +€9,162.51" on "Invested €25,038.01", Reports Savings
  value €39,044.83 vs Savings "Now worth €34,200.52". Three different numerators and two
  denominators, none labelled with its basis. Same page, two cash weights: Insights ›
  Rebalancing "Cash 32.0%" vs Composition "Cash 28.8%" (different denominators —
  targets exclude at-cost rows?). Sidebar "€39,045.00" vs hero "€39,044.83" (one path
  rounds, one doesn't).
- Proposal: a single `GainSummary` type from the API (`{ value, costOfOpen, netContributed,
unrealized, realized, income }`) and a UI rule: every gain figure carries a 3-word
  basis label ("vs cost of holdings" / "vs net contributed") and the two headline
  numbers (Holdings, Savings) link to the same explainer sheet. Fixing B6 removes the
  €39k/€34k split; this removes the remaining confusion.

### G3 · At-cost holdings should not look like "+€0.00 / 0.00%" in green

- Observed (desktop Holdings): BYON and IWDA rows show `+€0.00` / `0.00%` in success
  green with a small "AT COST" chip, plus a hero banner "Includes one or more holdings
  shown at cost".
- Proposal: P&L cell renders "—" with the chip carrying a tooltip ("No market price;
  valued at cost"), the hero banner becomes "2 holdings at cost" linking to the filtered
  list, and the asset-class donut hatches the at-cost share (ties to B7).

### G4 · URL is the state

- Observed: portfolio/holder scope lives in a cookie (`pf`), chart range and period in
  component state; only `/holdings?portfolio=` and `tax?year` are deep-linkable;
  `period-selector.tsx` (URL-driven) exists but has zero importers.
- Proposal: `?scope=` (`all|p:<id>|h:<id>`), `?range=`, `?period=` as searchParams read
  by the RSC loaders, cookie only as the default for scope-less URLs. Enables share
  links, browser back, and the PWA restoring exactly where you were.

### G5 · Money never truncates; tables never clip silently

- Observed: Reports cards at 390 px show "€44…", "€570…", "REALIZED ALL…", "AVG H…";

- Proposal: metric rows use `formatMoneyCompact` (exists) below `sm` and

  scroll shadows (CSS only) and switch to the card list below `lg`, not `md`; lists get
